Yummle v1.3.7 makes YouTube cookies observable and lets the save userscript mark videos watched at YouTube: the Settings page now reports whether your `cookies.txt` is actually usable (and can prove it with one real request), a new capabilities endpoint tells the browser script what the server can do, and saving a video from YouTube can record it in your YouTube watch history at the same time — with bulk flows (channels, scans, auto-downloads) always excluded.

## Added

- **YouTube cookie status on the Settings page.** `KAPSEL_YTDLP_COOKIES_FILE` becomes a first-class, observable setting: the readiness check reports configured → readable → contains a signed-in session (mirroring yt-dlp's own definition: a `LOGIN_INFO` cookie plus a SAPISID-family cookie, so a file with only anonymous or half-exported cookies is correctly rejected), shows the earliest signed-in cookie's expiry, and starts warning 14 days out. A "Test YouTube cookies" button runs one real yt-dlp request to prove the session is live end-to-end, rate-limited to one attempt per two minutes with a visible countdown. Previously a misconfigured cookies setup was invisible until a download failed deep in a job log.
- **A save button that tells you the truth.** The Yummle save userscript (v0.4.2) asks the server once per page what it supports and adjusts its tooltip accordingly — including the reason when watch-marking is unavailable (no cookies configured, unreadable file, no signed-in session). A failed or unauthenticated capability check degrades to the default copy; saving always still works. A new cheap `GET /api/capabilities` replaces per-page calls to the much heavier settings endpoint.
- **Saving a video can mark it watched on YouTube.** When the save request asks for it, the download now runs yt-dlp with `--mark-watched`, which records the video in your YouTube account's watch history during extraction — no extra requests, and bulk flows (channel scans, playlist imports, auto-downloads) never send the flag. If the cookies check fails at run time, the download still proceeds and the job result records `mark_watched: "skipped"` with the reason, so you can see why instead of guessing.

## Notes

- **The mark fires during the download, not after.** A download that later fails can still leave the video "watched" — accepted, since the ping happens at extraction time by design.
- **Watch history progress can read below 100%.** Known yt-dlp behavior (`--mark-watched` marks the history entry without driving playtime to full); not retried or repaired.
- **The static check is deliberately cheap, not authoritative.** Command building consults a file-level check only (no network); only the settings probe can confirm a live session against YouTube.
- **Upgrading the userscript is required for marking.** Older script versions keep working but never send the flag; the server-side prerequisite applies regardless of what client asks.
- **No data migrations and no configuration changes.** The feature is dormant unless a save request asks to mark watched.

No upgrade steps: nothing to migrate, nothing to configure. To use the new marking, point `KAPSEL_YTDLP_COOKIES_FILE` at a signed-in `cookies.txt` (scripts/export-cookies.sh) and use the updated userscript.
